# I gave OpenAI's Decisions API a quiz written by lawyers

By Zoeb Nomi. Write-up with the answer sheet, the table and a narrated
version: https://www.zoebnomi.com/writing/decisions-api-legal-quiz/

A one-day test of whether the probability returned by OpenAI's Decisions API
(`POST /v1/decisions`, model `gpt-6-luna`, public beta) can be trusted on
lawyer-labelled yes/no legal questions, and whether there is a confidence
threshold above which its answers can be left unchecked.

Short answer: no such threshold shows up. At confidence 0.9 or higher the
model is 87.5% accurate on 72% of items. At 0.99 it is 90.3% accurate on
49% of items. The errors are mostly confident "no"s on items lawyers marked
"yes". Full write-up in [FINDINGS.md](FINDINGS.md).

## Dataset and attribution

[LegalBench](https://github.com/HazyResearch/legalbench) (Guha et al., 2023),
test splits from the Hugging Face mirror `nguha/legalbench`. The three
`cuad_*` tasks are derived from CUAD (The Atticus Project, CC BY 4.0).
LegalBench tasks carry their own licences; the six used here are listed as
CC BY 4.0 on the dataset card, which you should verify before redistributing
more than the excerpt in this repo. `data/sample_20.jsonl` is a 20-row excerpt
of one task, sampled and relabelled (Yes/No to true/false); the full 544-row
sample is regenerated by `load_legalbench.py` and is not committed.
Six binary tasks, 544 items:

| task | items | yes | no | source |
|---|---|---|---|---|
| cuad_anti-assignment | 100 | 50 | 50 | CUAD clause classification |
| cuad_non-compete | 100 | 50 | 50 | CUAD clause classification |
| cuad_change_of_control | 100 | 50 | 50 | CUAD clause classification |
| hearsay | 94 (all) | 41 | 53 | legal reasoning, fact patterns |
| personal_jurisdiction | 50 (all) | 21 | 29 | legal reasoning, fact patterns |
| consumer_contracts_qa | 100 | 50 | 50 | consumer contract Q&A |

Sampling: seed 42, balanced 50/50 where the task has enough rows.
`data/sample_20.jsonl` is a 20-row excerpt; the full sample is regenerated by
`load_legalbench.py`.

## The one prompt

Each item is one API call with one predicate question. No examples, no system
prompt, no retries on the answer.

```json
{
  "model": "gpt-6-luna",
  "input": "<the clause or fact pattern>",
  "questions": [{"type": "predicate", "name": "answer", "instructions": "<the task's question>"}]
}
```

The task questions are LegalBench's own instruction lines (`data/prompts.json`),
except hearsay: the benchmark's one-liner ("Hearsay is an out-of-court statement
introduced to prove the truth of the matter asserted. Is there hearsay?") made
the model answer yes on almost every "no" item in a 10-row pilot, so the full
run uses a four-sentence statement of the rule. Both wordings are kept in
`data/prompts.json` and the pilot results for the original wording are in
`results/hearsay_verbatim_pilot.jsonl`.

## Results

523 items answered, 21 refused (all hearsay fact patterns, which describe
crimes). Predicted label = probability >= 0.5. Confidence = max(p, 1 - p).

| task | n | accuracy | AUROC | ECE | Brier | coverage at conf >= 0.9 | accuracy there |
|---|---|---|---|---|---|---|---|
| consumer_contracts_qa | 100 | 93.0% | 0.976 | 0.060 | 0.048 | 87% | 97.7% |
| cuad_non-compete | 100 | 88.0% | 0.949 | 0.086 | 0.104 | 83% | 90.4% |
| personal_jurisdiction | 50 | 84.0% | 0.913 | 0.115 | 0.124 | 16% | 100% |
| cuad_anti-assignment | 100 | 83.0% | 0.952 | 0.170 | 0.142 | 85% | 87.1% |
| cuad_change_of_control | 100 | 75.0% | 0.863 | 0.268 | 0.235 | 79% | 75.9% |
| hearsay | 73 | 74.0% | 0.786 | 0.129 | 0.197 | 48% | 80.0% |
| **overall** | **523** | **83.2%** | **0.894** | **0.103** | **0.140** | **72%** | **87.5%** |

Trust curve (coverage and accuracy at every threshold from 0.50 to 0.99):
`results/trust_curve.csv`. Static figure: `results/trust_curve.png`.
Animated version: `media/trust_curve.mp4`.

Cost: 192k input tokens including the 60-row pilot (190k for the main run,
`results/metrics.json`), $0.019 at $0.10 per 1M input tokens. About four
minutes at concurrency 8.

## Reproduce

Python 3.13 and ffmpeg 6 on the path. Each step needs the previous step's
output; `plot.py` alone works on a clean clone because `results/metrics.json`
and `results/trust_curve.csv` are committed.

```
pip install -r requirements.txt
export OPENAI_API_KEY=...                          # read from the environment only
python3 load_legalbench.py                         # data/sample.jsonl, data/prompts.json (needs huggingface.co)
python3 judge.py                                   # results/decisions.jsonl, resumable, about $0.02
python3 calibrate.py                               # results/metrics.json, trust_curve.csv, items.csv
python3 plot.py && python3 animate.py              # results/trust_curve.png, media/trust_curve.mp4
```

`judge.py --limit-per-task 10` runs a pilot. `judge.py --probe` prints one raw
response. `animate.py --storyboard` writes a three-frame still.

## Limitations

- One model, one call per item, zero-shot, the task's own question as the only
  instruction. Few-shot examples or a tuned prompt would likely change the
  numbers; the hearsay rewrite shows how sensitive they are.
- 50 to 100 items per task. Per-task accuracies carry a margin of roughly
  plus or minus 7 to 10 points.
- LegalBench items are short and self-contained. Nothing here speaks to long
  documents, defined terms or cross-references.
- Labels are the benchmark's. Items the model got "wrong" were not audited.
- No comparison to the Responses API or other models. This measures whether
  the Decisions probability can be trusted on its own, not whether it beats
  the alternatives.
